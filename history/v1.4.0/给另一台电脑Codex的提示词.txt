请接手「校园网共享助手」1.2.1，在当前这台通过 Wi-Fi 连接校园网的 Windows 电脑上，完成真实安装、联网共享和卸载恢复验收；遇到问题请根据证据修复并重新交付 EXE 安装包。请用中文沟通，面向不熟悉技术的使用者。

一、用户目标与这次问题
用户要一个便于别人安装的独立 EXE，界面能选择上网连接、输入校园账号密码、点击确认，支持有线和 Wi-Fi 接入后共享给手机，并可卸载后重新用原官方软件。
另一台电脑曾出现「快捷方式不对、找不到安装后的 EXE 本体」；用户使用的是 EXE 安装包，没有使用 ZIP。后来确认该电脑通过 Wi-Fi 而不是网线接入。不要把 ZIP 解压成功当作安装验收，也不要误以为必须接网线。

二、先找到材料，核实本机状态
材料所在文件夹名为「校园网共享助手-1.2.1」，可能在桌面或下载目录；用户名和盘符以本机为准。找不到时只向用户询问该文件夹位置，不假定仍在原开发机的 C:\Users\pc。
- 待测安装包：校园网共享助手-1.2.1-WiFi与有线版-x64.exe
- 校验文件：SHA256.txt。安装前核对 EXE 哈希与此文件一致。
- 使用说明.txt
- 维护源码：包含 payload、stage、build.py、setup.iss、测试和纯净 upstream.zip；stage 是干净构建文件，不能用它替代 EXE 安装验收。
- 实机验收记录.md：逐项更新实际结果，不把未知填成通过。
旧开发机有正在工作的独立共享方案，未在其上接管网络或进行新包的实机验证。不要把旧机的配置、账号、SSID、网卡 GUID 或会话复制到本机。

三、先只读诊断，再安排实测
先记录 Windows 版本/架构、无线网卡型号和驱动、当前校园 Wi-Fi 的网络配置名称、网卡标识、IPv4/网关/子网、原官方客户端名称和安装位置、现有热点状态/共享来源、默认路由、是否存在 VPN/代理和旧助手配置。不要关闭 VPN/代理来凑出测试成功。
首先查明这台电脑日常通过哪种方式完成校园无线认证，验证原官方方式能实际打开网页。1.2.1 仍使用广东天翼 ESurfingClient-CVersion 2.2.0-r4；新增 Wi-Fi 枚举不意味着自动兼容网页认证、802.1X 或所有校园 Wi-Fi。认证方式不同，应先定位差异，不能先修改网络再猜。
要重启、停止认证、切换连接或真实卸载恢复之前，先说明具体影响并确认用户方便短暂断网的测试时间。已有明确授权的步骤不重复询问。用户填写自己的账号密码，不要求把密码发到聊天里。
保存本地必要的恢复基线。不要在对话、截图、报告或分发包中输出密码、令牌、会话、完整认证配置。不要上传原始认证日志。

四、已做的修改与证据边界
1. 主程序改为「校园网共享助手.exe」，无参数双击就能打开面板；桌面和开始菜单快捷方式指向它，工作目录是安装目录。保留 CampusQuietLauncher.exe 供计划任务使用。
2. 面板有「安装文件夹」，开始菜单有「打开安装文件夹」。默认安装位置是 C:\Program Files\GDPortalShare，实际系统盘以本机为准。启动错误会显示提示，不能只看进程存在。
3. 正式安装记录对应目录时可覆盖修复文件和快捷方式，保留运行配置和原恢复备份。先关闭旧助手窗口；来源不明的同名目录会阻止安装，不能直接删掉目录绕过。
4. 可选择物理 Wi-Fi 或有线网卡。Wi-Fi 保存网络配置名称，启动、恢复和更新账号会核对选定网络。绑定还包括网卡 GUID、网关和子网；同名校园 Wi-Fi 漫游到不同网段也可能等待连接，需要诊断。更新账号不能当作更换网卡的入口。
5. 已通过离线网络选择与匹配、更新账号防止串到另一 Wi-Fi、脚本与回滚模拟、表单确认/取消、编译启动器入口与互斥测试。曾用同一安装文件映射和快捷方式逻辑完成隔离真实安装及链接启动；最终 1.2.1 EXE 的全部 33 个内置文件再经哈希核对。
6. 尚未在这台目标电脑验证真实校园 Wi-Fi 认证、无线网卡并发热点、手机联网、重启自动恢复及卸载后的官方登录。这些才是当前任务，不要将离线测试或界面显示「完成」当成实机通过。

五、按实际顺序验收
A. 原官方方式：连接校园 Wi-Fi，确认电脑实际访问新网页成功，记录认证方式与基线。
B. 独立 EXE 安装：用上述安装包安装/修复，确认主 EXE、Panel.ps1、Manage.ps1、Network.ps1 和 Client 中认证组件实际存在；核对桌面/开始菜单快捷方式的目标、参数、工作目录。分别实际打开桌面入口、开始菜单入口以及主 EXE，确认可见面板正常。检查「安装文件夹」按钮。
C. 图形设置：下拉框应显示正在使用的校园 Wi-Fi；先验证取消不写配置，再由用户输入账号密码确认。确认备份与任务正确建立，配置绑定的是当前 Wi-Fi。若已有旧配置绑定其他网卡，先判断并通过正常卸载恢复后重新设置，不覆盖 original-startup.json。
D. 自动启动：取得测试窗口授权后由用户手动重启并登录，等待约 1–5 分钟；确认认证真正成功、电脑能上网、热点共享来源为所选 Wi-Fi。检查是否有多个认证进程争抢，必须按路径确认归属后处理。
E. 手机验收：让用户关闭手机移动数据、连接此电脑热点、访问至少两个此前未打开的新网页；同时电脑继续联网。手机是否能访问必须由真实结果判断，不能由 API 状态或热点开关替代。
F. 再次重启：观察是否自动恢复认证与热点，重复手机实测。若这步暂无条件，明确记为待测。
G. 回滚：先测试在卸载确认页面取消后设置和连接仍正常；再在授权时间内通过「卸载并恢复官方软件」执行真实恢复。恢复失败保留目录、卸载器和备份，定位后重试，不能直接删文件。卸载后重启，用原官方客户端实际登录并访问网页，核对本助手任务/自建路由和所修改设置已恢复。
H. 有线回归：如果现场有网线与校园有线接入条件，再测试有线流程；没有就明确标记「有线实机未测」，不可把 Wi-Fi 成功写成两种方式都实测通过。

六、回滚边界与故障分层
现有回滚恢复记录过的官方启动项、服务启动方式、接口 metric，移除自身的任务/路由并停止自身认证进程；不会重装官方软件，测试前须确认原官方软件仍保留。当前版本未备份和恢复 Windows 热点原有开关及共享来源，必须记录基线；必要时说明差异并在用户同意后还原，不宣称「所有网络设置完全恢复」。
遇到失败，先区分：文件/快捷方式问题、界面问题、Wi-Fi 候选或绑定问题、校园认证协议问题、网卡热点能力问题、共享来源/路由问题。保持可恢复现场，避免反复重启或盲目重置网络。
已有热点被复用时状态可能是 existing-hotspot-check-upstream，需要在 Windows 热点设置核对共享来源；not-at-campus 则检查名称、网关、子网和 GUID 是否与首次配置一致。

七、排查入口及源码
安装目录下：last-status.json、startup.log、startup.previous.log、watchdog-status.json、recovery-last-result.json；settings.json 仅提取必要网络字段并脱敏；original-startup.json 与 managed-routes.json 是恢复依据，要保留。启动器日志：%LOCALAPPDATA%\GDPortalShare\launcher.log。
计划任务：GDPortalShare-Logon、GDPortalShare-Logon-Watchdog。
Client\ESurfingClient.json、同名 .pending 和认证日志可能含凭据，禁止直接打印或打包分享。
源码中 Network.ps1 负责候选与网络匹配，Manage.ps1 负责设置/备份/卸载，Start-CampusNetwork.ps1 负责认证与热点，Watch-CampusNetwork.ps1 负责守护，Campus-Recovery.ps1 负责恢复操作，Panel.ps1 和 CampusQuietLauncher.cs 负责可视化入口，setup.iss/build.py 负责打包。
需要修复时先保存现场证据，修改「维护源码」，进行相应测试、重新构建并验证最终 EXE，再通过安装包验证修复；不要仅热改安装目录后宣布交付成功。构建依赖见维护源码\接手说明.md。

八、完成标准
继续工作到所有有现场条件且获准的项目完成。需要用户操作手机、填写密码或重启时明确说出这一步要做什么。每个结果写入「实机验收记录.md」：证据、是否通过、失败原因、恢复结果；未测项明确标注。最后说明当前电脑最终处于助手共享模式还是官方软件模式，并交付确切版本和本地安装包路径。只有手机实际联网和卸载后官方实际联网均验证过，才宣称该电脑的共享与回滚实机通过。
