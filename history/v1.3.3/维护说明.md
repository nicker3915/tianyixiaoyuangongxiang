# 校园网共享助手 1.3.3 维护说明

这是基于收到的 1.3.2 维护源码完成的发布整理版本。Windows x64 安装器和主程序版本统一为 1.3.3，认证组件仍使用固定哈希的 ESurfingClient-CVersion 2.2.0-r4。

## 本次修改

- 安装器在复制文件后验证全部 34 个发行组件的 SHA-256；缺文件或内容不同会记录失败，不执行安装器自动启动，返回非零退出码。校验失败后已经落盘的文件可能仍存在，用户不得将其当作完整安装使用，应核对后修复。
- 安装器在覆盖之前检查助手面板或设置/恢复操作的命名互斥；有操作正在进行时提示退出，不强制停止认证。升级仍要求使用者先正常停止共享，完全退出窗口和托盘。
- 补全安装包与主 EXE 的版本信息、卸载图标、更新账号与更换网卡的说明。
- Network、Manage、Lifecycle、Start、Watch、Recovery 六个模块与收到的 1.3.2 在 BOM/换行标准化后内容完全相同，保持已反馈可用的认证与共享逻辑。
- 分享与维护压缩包使用正确的 UTF-8 中文文件名，剔除旧版本安装包、编译器安装文件、运行日志和机器专属配置。

## 构建与验证

需要 Windows x64、Python 3、Windows PowerShell 5.1、系统 .NET Framework C# 编译器和 Inno Setup 6.4.1。普通使用者安装 EXE 无需这些开发工具。

build.py 先读取环境变量 ISCC，再查 PATH，最后尝试原开发环境的 Antigravity IDE 路径。换电脑时应先确认 ISCC.exe 的实际位置，用当前进程环境变量指定即可，不改系统级设置。源码包不携带整套编译器。

```
python build.py
python verify-binary.py "dist\校园网共享助手-1.3.3-安装程序.exe"
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File test-offline.ps1
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File test-network-selection.ps1
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File test-lifecycle.ps1
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File test-ui.ps1
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File test-panel.ps1
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File test-entrypoints.ps1
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File test-recovery-wait.ps1
python test-installer.py
```

以上脚本参数仅作用于测试或应用子进程，不修改系统执行策略，不关闭 Defender、SmartScreen、AMSI 或智能应用控制，不绕过单位强制策略。测试使用虚构数据和独立目录。test-recovery-wait 在测试夹具中移除 UAC 交互、避免重定向管道，只验证进程等待语义；不证明真实 UAC 流程已经实机验收。

test-installer.py 使用正式文件映射、哈希检查、图标与卸载回调，在独立目录进行安装；权限、安装路径、注册项和自动启动动作被隔离，卸载恢复脚本换成无网络副作用的测试替身。它验证文件、入口与回调门控，不能代替真实校园网和官方软件的端到端验收。

快捷方式测试通过 COM 检查目标、参数和工作目录，再用解析出的目标实际启动安装后的 EXE，避免自动化环境中的 Shell 交互影响测试。它不代表所有目标电脑的 Explorer、SmartScreen 或智能应用控制均已放行。

## 分发与签名

SHA-256 校验能够核对文件是否相同，不能证明发布者身份，也不能代替可信签名。本地未发现可用的代码签名证书，因此本次产物保持明确标注为未签名；未生成自签名证书来冒充可信发布者。

后续若取得可信代码签名身份，应为自有启动器、脚本和安装器建立签名及时间戳流程；签名应在计算发行哈希前完成，最终安装包签名后重算外部 SHA-256。第三方客户端还需满足目标电脑对所有可执行文件的策略，不能只给外层安装包签名就宣称内部程序一定放行。

不要加入关闭防护、白名单排除、修改 SmartScreen/SAC 策略、清除来源标记或混淆程序来规避检测的操作。确有 Defender 误报时，应先核对文件及检测名称，再走微软误报提交渠道。

维护时保留用户首次 original-startup.json。不得将已安装 Client、settings.json、账号、会话、运行日志或网卡身份打入发布包。
